# Прогнозирование концентрации PM2.5 в Красноярске (дипломный проект)

Дипломный проект по моделированию загрязнения воздуха мелкодисперсными частицами PM2.5 в Красноярске на основе данных городских датчиков и метеорологических параметров, включая вертикальный профиль атмосферы.

Проект изначально был выполнен в Jupyter Notebook. Сейчас я постепенно переношу его в структурированный Python-пакет с воспроизводимым пайплайном (DVC для данных, MLflow для экспериментов, uv для окружения).

> **Статус: в процессе миграции.** Часть этапов уже вынесена в модули с CLI-командами, часть пока живёт в ноутбуках (см. [Статус этапов](#статус-этапов)).

## Идея

Концентрация PM2.5 в городе зависит не только от выбросов, но и от того, насколько хорошо атмосфера их рассеивает: ветер, температурные инверсии, устойчивость пограничного слоя. Для описания этого эффекта используется простая модель ящика, в которой рассеивание сводится к одному коэффициенту **K**:

```
K(t) = PM2.5(t+1) / (E(hour) + PM2.5(t))
```

- `PM2.5(t)` — средняя по датчикам концентрация за час `t`;
- `E(hour)` — средний «выброс» для данного часа суток (среднее PM2.5 по всем дням для этого часа);
- `K` — целевая переменная, которую предсказывает модель по метеорологическим признакам.

Дальше по метеоданным (температура на разных высотах, ветер, давление, числа Ричардсона и т. д.) строится регрессионная модель для `K`, а из набора признаков отбираются наиболее значимые.

## Данные

| Источник | Что берём | Как |
|---|---|---|
| [air.krasn.ru](http://air.krasn.ru) (API 2.0, проект `9`) | Почасовые измерения PM2.5 по датчикам города | `ingestion.get_pm25_data` |
| [Open-Meteo Historical Forecast API](https://open-meteo.com/) | Почасовая метеорология для координат 56.0267, 92.9077 | `ingestion.get_historical_weather_data` |

Метеопараметры: температура на 2/80/120/180 м, скорость и направление ветра на 10/80/120/180 м, относительная влажность, давление (на уровне моря и поверхности), осадки, коротковолновая радиация. Схема ответа API с данными о загрязнении описана в [`data/raw/krasair_data_schema.txt`](src/bachelor_project/data/raw/krasair_data_schema.txt).

Данные в репозиторий не коммитятся: CSV лежат под контролем **DVC** (в git хранятся только `.dvc`-файлы).

## Пайплайн

```
 load-data            preprocessing           feature-engineering        split-data            feature-selection
┌──────────┐        ┌───────────────┐        ┌──────────────────┐      ┌───────────────┐      ┌──────────────────┐
│ air.krasn│  raw   │ очистка, K    │ k_data │ Ri, инверсии,    │ feat │ train/val/test│      │ Random Forest +  │
│ Open-Met.│ ─────▶ │ (ноутбук)     │ ─────▶ │ скользящие 24ч   │ ───▶ │ + StandardScal│ ───▶ │ permutation imp. │
└──────────┘        └───────────────┘        └──────────────────┘      └───────────────┘      └──────────────────┘
```

1. **Загрузка** (`ingestion`) — выгрузка PM2.5 по дням из API и погоды из Open-Meteo в `data/raw/`. Учитывается, что Open-Meteo отдаёт время по Гринвичу, поэтому стартовая дата сдвигается на день назад.
2. **Препроцессинг** (`notebooks/preprocessing.ipynb`) — приведение к часовому поясу `Asia/Krasnoyarsk`, фильтрация данных с 2023-01-01, удаление датчиков `3850`, `4324`, `4364`, линейная интерполяция пропусков внутри ряда, усреднение по датчикам, расчёт `E(hour)` и `K`, объединение с метео.
3. **Генерация признаков** (`feature_engineering`):
   - вертикальные инверсии температуры (`max_inv`, `mean_inv`, `grad_80_180_inv`, `inv_height`);
   - bulk-числа Ричардсона между 2 м и 80/120/180 м (`max_Ri`, `mean_Ri`, `grad_80_180_Ri`);
   - синус/косинус направления ветра, сдвиг ветра (`wind_shear`);
   - скользящее среднее за 24 часа для каждого признака (суффикс `_roll24`).
4. **Разбиение и стандартизация** (`splitting`) — хронологическое разбиение по годам: **train — 2023, val — 2024, test — 2025**. `StandardScaler` обучается только на train и сохраняется в `model/scaler.pkl`.
5. **Отбор признаков** (`training`) — подбор гиперпараметров Random Forest (`RandomizedSearchCV` + `TimeSeriesSplit`, 5 фолдов), ранжирование признаков по permutation importance, затем выбирается минимальное число признаков, при котором train R² достигает 95% от R² на полном наборе. Все прогоны логируются в MLflow, результат сохраняется в `artifacts/feature_selection/`.

## Быстрый старт

Требуется Python 3.12 и [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/GraffiasAntares/bachelor_project.git
cd bachelor_project
uv sync
```

Данные можно скачать заново командой `load-data` (см. ниже). Версии файлов зафиксированы в `.dvc`-файлах; подтянуть их через DVC можно только при настроенном remote (конфигурация DVC в репозиторий не входит), при этом сам DVC нужно установить отдельно, например `uv tool install dvc`:

```bash
dvc pull
```

### Запуск этапов

```bash
# 1. Загрузка данных за период [start_date; end_date), формат YYYY-MM-DD
uv run load-data 2023-01-01 2026-01-01

# 2. Препроцессинг — пока вручную: notebooks/preprocessing.ipynb

# 3. Генерация признаков
uv run get-features

# 4. Разбиение на train/val/test и стандартизация
uv run split-data

# 5. Отбор признаков (нужен запущенный MLflow-сервер, см. ниже)
uv run feature-selection
```

Быстрая проверка загрузки данных на одном дне (результат пишется в `data/raw/test_*.csv`):

```bash
uv run test-load-data
```

### MLflow

Отбор признаков логирует эксперимент `feature_selection_by_random_forest` на `http://127.0.0.1:5000`. Перед запуском поднимите сервер:

```bash
uv run mlflow server --host 127.0.0.1 --port 5000
```
